# 项目结构说明

## 项目概述

**Shoplazza Merchant Simple Ticket Support System（商家售后工单系统）**

基于 Shoplazza 开放平台的售后工单客服系统。支持多店铺管理、Webhook 实时触发 + API 定时兜底、邮件通知、顾客自助工单。

技术栈：Node.js 18+ / TypeScript / Express / PostgreSQL 16 / Docker

### `src/` — 后端 TypeScript 源码

#### 核心入口

| 文件 | 说明 |
|------|------|
| `index.ts` | **Express 应用入口** — 启动服务器，加载配置，连接数据库，注册路由和中间件（CORS、限流、安全头），启动定时器（邮件发送、兜底同步、日志清理） |
| `config.ts` | **配置加载** — 从环境变量读取配置（端口、数据库、SMTP、Token 密钥等），店铺配置加载（DB 优先，fallback 到环境变量 JSON） |
| `pg.ts` | **PostgreSQL 连接池** — 初始化连接池，建表（`support_order_snapshots`、`support_email_events`、`support_email_jobs`、`support_email_templates` 等），提供 query/getClient 工具 |

#### 认证与安全

| 文件 | 说明 |
|------|------|
| `auth.ts` | **管理员认证** — 密码加盐哈希（scrypt）、管理员登录/登出、Session 管理（7 天有效期）、密码修改 |
| `token.ts` | **顾客访问令牌** — 生成两种令牌：bootstrap token（`bt_` 前缀，30 天有效期）和 ticket access token（`ta_` 前缀，90 天有效期），令牌 SHA256 哈希后存库 |

#### 路由层

| 文件 | 说明 |
|------|------|
| `admin-routes.ts` | **管理员 API 路由** — 登录/登出/修改密码、工单列表/详情/回复/状态变更、邮件任务管理（列表/详情/重发/取消）、店铺 CRUD、邮件模板管理（列表/编辑/预设切换）、系统设置（自动发送/兜底/邮件测试模式/公网域名）、同步日志/操作日志查询、Webhook 注册/删除/列表、顾客预览数据 |
| `support-routes.ts` | **顾客端 API 路由** — bootstrap 初始化（验证令牌返回订单信息和工单状态）、创建工单、查看工单详情、顾客回复、关闭工单、申请仲裁 |
| `shoplazza-webhook-routes.ts` | **Shoplazza Webhook 路由** — 接收 `orders/paid` 等事件推送，去重写入 `shoplazza_webhook_events`，补查订单详情和交易记录，写入订单快照，创建邮件任务 |

#### 业务服务层

| 文件 | 说明 |
|------|------|
| `ticket-service.ts` | **工单 CRUD** — 创建工单（生成 public_ticket_no + access token）、获取工单详情/消息列表、顾客/客服添加消息、连续消息限制（最多 5 条）、关闭工单、申请仲裁、订单快照查询、工单列表分页查询 |
| `email-service.ts` | **邮件服务** — 邮件任务创建（下单引导 `paid_support_invite`、客服回复通知 `agent_reply_notice`、工单关闭通知 `ticket_closed_notice`）、邮件渲染（支持模板 + Mustache 变量替换）、邮件发送队列处理、模板管理（预设切换 CRUD）、系统设置（自动发送/测试模式/公网域名） |
| `store-service.ts` | **店铺管理** — 店铺 CRUD（`support_stores` 表）、Access Token AES-256-GCM 加密存储/解密、店铺列表/启用店铺查询 |
| `backfill-jobs.ts` | **兜底同步任务** — 每小时增量拉取已支付订单（按 `updated_at` 过滤），逐条补全订单快照和邮件任务，支持手动触发单店铺/全店铺同步 |
| `mailer.ts` | **邮件发送** — Nodemailer 封装，支持 Mailpit 测试模式和生产模式（阿里云邮件推送等），Transporter 复用与自动重建 |

#### 数据层与工具

| 文件 | 说明 |
|------|------|
| `normalize-order.ts` | **订单数据标准化** — 将 Shoplazza API 返回的原始订单/交易数据统一成内部 `NormalizedOrder` 格式（提取邮箱、姓名、卡号后四位、支付时间等） |
| `shoplazza-client.ts` | **Shoplazza API 客户端** — 封装订单详情/交易查询、已支付订单列表拉取（Cursor 分页）、Webhook 管理（注册/列表/删除/查找），内置限流（550ms 间隔）和超时控制 |
| `log-service.ts` | **日志服务** — 同步日志（`support_sync_logs`，30 天自动清理）+ 操作日志（`support_operation_logs`，永久保留），含分页查询和自动清理功能 |
| `admin-preview.ts` | **管理员预览顾客端** — 构建顾客预览响应数据（脱敏，不含 token），物流单号智能提取 |

## 数据流概览

```
Shoplazza 店铺
    │
    ├─ orders/paid Webhook ──→ shoplazza-webhook-routes.ts
    │                              │
    │                              ├─ 写入 shoplazza_webhook_events（去重）
    │                              ├─ 调用 Shoplazza API 补全订单详情
    │                              ├─ 写入 support_order_snapshots（幂等 UPSERT）
    │                              └─ 创建 support_email_jobs（paid_support_invite）
    │
    ├─ API 兜底（每小时） ──→ backfill-jobs.ts
    │                           │
    │                           ├─ 按 updated_at 增量拉取已支付订单列表
    │                           ├─ 逐条补齐 support_order_snapshots
    │                           └─ 逐条创建 support_email_jobs
    │
    └─ 店铺管理（管理员） ──→ admin-routes.ts → store-service.ts
                                │
                                ├─ CRUD support_stores（Token 加密存储）
                                └─ 注册/删除 Shoplazza Webhook

顾客端（ticket.html）
    │
    ├─ GET  /api/support/bootstrap?t=TOKEN  ──→ support-routes.ts
    ├─ POST /api/support/tickets              ──→ support-routes.ts → ticket-service.ts
    ├─ GET  /api/support/tickets/:no?t=TOKEN  ──→ support-routes.ts → ticket-service.ts
    ├─ POST /api/support/tickets/:no/messages  ──→ support-routes.ts → ticket-service.ts
    └─ POST /api/support/tickets/:no/close     ──→ support-routes.ts → ticket-service.ts

客服端（admin*.html）
    │
    ├─ POST   /api/admin/login                  ──→ admin-routes.ts → auth.ts
    ├─ GET    /api/admin/tickets                ──→ admin-routes.ts → ticket-service.ts
    ├─ GET    /api/admin/tickets/:no            ──→ admin-routes.ts → ticket-service.ts
    ├─ POST   /api/admin/tickets/:no/reply      ──→ admin-routes.ts → ticket-service.ts (→ email-service)
    ├─ GET    /api/admin/email-jobs             ──→ admin-routes.ts → email-service.ts
    ├─ POST   /api/admin/email-jobs/:id/resend  ──→ admin-routes.ts → email-service.ts
    ├─ GET    /api/admin/stores                 ──→ admin-routes.ts → store-service.ts
    ├─ POST   /api/admin/stores                 ──→ admin-routes.ts → store-service.ts
    ├─ ...其他管理接口
    └─ GET    /api/admin/sync-logs              ──→ admin-routes.ts → log-service.ts
```

## 数据库表一览

| 表名 | 说明 |
