建议把它做成一个订单邮件管理模块，不要只是简单扩展 support_email_events。因为你现在要看的字段已经接近“邮件任务队列 + 发送记录 + 手动补发管理”。

建议新增表：support_email_jobs

这个表负责管理每一封要发/已发/失败/补发的邮件。

CREATE TABLE IF NOT EXISTS support_email_jobs (
  id BIGSERIAL PRIMARY KEY,

  email_job_no TEXT UNIQUE NOT NULL,

  store_subdomain TEXT NOT NULL,
  store_name TEXT,
  store_domain TEXT,
  mail_domain TEXT,

  order_id TEXT NOT NULL,
  order_number TEXT,
  ordered_at TIMESTAMPTZ,

  public_ticket_no TEXT,

  email_type TEXT NOT NULL,
  customer_email TEXT NOT NULL,

  status TEXT NOT NULL DEFAULT 'pending',

  scheduled_at TIMESTAMPTZ,
  sent_at TIMESTAMPTZ,
  failed_at TIMESTAMPTZ,

  retry_count INTEGER NOT NULL DEFAULT 0,
  last_error TEXT,

  subject_snapshot TEXT,
  body_snapshot TEXT,
  client_link_snapshot TEXT,

  token_id BIGINT,
  manual_resend_of BIGINT,

  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_support_email_jobs_order
  ON support_email_jobs(store_subdomain, order_id);

CREATE INDEX IF NOT EXISTS idx_support_email_jobs_status
  ON support_email_jobs(status, scheduled_at);

CREATE INDEX IF NOT EXISTS idx_support_email_jobs_customer
  ON support_email_jobs(customer_email);

CREATE INDEX IF NOT EXISTS idx_support_email_jobs_type
  ON support_email_jobs(email_type);

手动补发按钮怎么做

后台列表里每条失败或已发送邮件都可以有按钮：

补发

接口：

POST /api/admin/email-jobs/:id/resend

逻辑：

1. 查原 email job
2. 重新生成新的 token，避免旧链接过期或泄露
3. 复制原订单信息、邮件类型、收件人
4. 创建一条新的 support_email_jobs
5. manual_resend_of = 原 job id
6. scheduled_at = now()
7. worker 立即发送

不要直接把原记录改成 pending。补发应该生成新记录，这样审计清楚。

客户端链接要注意安全

你要展示“工单客户端链接”，可以做，但有一个安全点：

不要长期明文保存完整 token 链接。

推荐做法：

support_access_tokens
  保存 token_hash 和 token 元信息

support_email_jobs
  保存 token_id
  client_link_snapshot 可以保存脱敏链接

例如后台显示：

https://support.yourdomain.com/ticket?t=bt_abcd...wxyz

真正需要复制完整链接时，由后台重新生成一个新的访问 token，或者只允许管理员点击“复制新链接”。

如果你们确实要保存完整邮件内容快照，建议：

1. body_snapshot 里链接做脱敏
2. 或者 body_snapshot 加密存储
3. 补发时重新渲染邮件，不直接复用旧 token

      },
      "financial_status": "paid",

  }'

SELECT *

2. 本地测试邮件，用 Mailpit

本地不用真实发邮件，用 Mailpit。

docker-compose 里加：

mailpit:
  image: axllent/mailpit:latest
  ports:
    - "8025:8025"
    - "1025:1025"

本地环境变量：

SUPPORT_PUBLIC_BASE_URL=http://localhost:4001

SUPPORT_MAIL_FROM="Local Support <no-reply@local.test>"
SUPPORT_MAIL_REPLY_TO=no-reply@local.test

SUPPORT_SMTP_HOST=mailpit
SUPPORT_SMTP_PORT=1025
SUPPORT_SMTP_SECURE=false
SUPPORT_SMTP_USER=
SUPPORT_SMTP_PASS=

打开：

http://localhost:8025

你能看到所有测试邮件。

邮件里的链接可以是：

http://localhost:4001/ticket?t=bt_xxxxx

只要你在本机打开，就没问题。

如果想用手机测页面，把 SUPPORT_PUBLIC_BASE_URL 改成局域网 IP：

SUPPORT_PUBLIC_BASE_URL=http://192.168.1.23:4001

手机和电脑在同一 Wi-Fi 下即可访问。
