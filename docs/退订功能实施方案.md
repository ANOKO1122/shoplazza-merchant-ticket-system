# 退订功能实施方案（商户级 HMAC 无状态退订）

> **设计原则**：基于 HMAC-SHA256 签名实现**无状态（Stateless）退订链接**，退订粒度锁定在**"邮箱 + 店铺"**维度，避免跨店铺"误杀"。

---

## 一、背景与业务约束

### 1.1 为什么要做退订

- **阿里云 DirectMail 合规要求**：iCloud/Gmail 用户点击"垃圾邮件"举报会反馈到阿里云授信系统，举报率超标将导致发信功能直接被封禁。
- **邮件入箱率保障**：提供退订渠道可大幅降低被标记为垃圾邮件的概率。
- **RFC 8058/2369 标准**：现代邮件系统要求提供 `List-Unsubscribe` 机制。

### 1.2 收单方聚合客服的特殊风险

当前系统服务**多个独立站商户**（如 Store A、Store B 共用同一套客服系统）。如果做**全局退订**（按邮箱），会出现**业务误杀**：

```
买家在 A 店退订 → 邮箱进入全局黑名单
→ 买家在 B 店的新订单邮件也被拦截
→ B 店商户投诉"系统故障"
→ 买家收不到交易凭证，可能发起 Chargeback（拒付）
```

**结论：必须将退订粒度锁定在"邮箱 + 店铺"维度。**

### 2.2 HMAC 签名设计（核心）

#### 2.2.1 签名算法

```
签名明文格式:  {email}|{store_subdomain}[|{timestamp}]
签名算法:      HMAC-SHA256(明文, SECRET)
输出编码:      base64url (URL-safe)
```

#### 2.2.2 必须包含 `store_subdomain` 的原因

```typescript
// ❌ 错误：只签邮箱，买家可跨店撞链接
hash = HMAC("user@icloud.com", SECRET)

// ✅ 正确：签邮箱+店铺，A店退订链接不能用于B店
hash = HMAC("user@icloud.com|store-a.myshoplaza.com", SECRET)
```

防止买家拿着在 A 店生成的退订链接，恶意去撞 B 店的退订接口。

#### 2.2.3 可选：加入时间戳控制有效期

```typescript
// 带时间戳版本（推荐）
plaintext = `user@icloud.com|store-a.myshoplaza.com|1717286400`
sig = base64url(HMAC-SHA256(plaintext, SECRET))
// 链接: /unsubscribe?e=...&s=...&t=1717286400&sig=xxxx
```

后端校验时除验证签名外，还可校验 `t` 是否在有效期内（如 30 天），超期则提示"链接已过期，请联系客服"。

#### 2.2.4 密钥管理警告

- **密钥来源**：复用现有 `SUPPORT_TOKEN_SECRET` 环境变量（或使用独立的 `SUPPORT_UNSUBSCRIBE_SECRET`）
- **绝对不能随意更改**：一旦更换密钥，之前所有邮件里的退订链接全部失效
- **安全存储**：仅存在于服务端环境变量，不写入日志、不返回前端

### 2.3 数据库设计

#### 新表：`support_unsubscribes`

```sql
CREATE TABLE IF NOT EXISTS support_unsubscribes (
    id BIGSERIAL PRIMARY KEY,
    customer_email TEXT NOT NULL,
    store_subdomain TEXT NOT NULL,
    email_type TEXT,                          -- NULL = 退订该店铺所有类型邮件
    source TEXT NOT NULL DEFAULT 'link',      -- 'link' | 'manual'（管理员手动添加）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(customer_email, store_subdomain, COALESCE(email_type, '__all__'))
);

-- 索引（发信前查询需要极其高效）
CREATE INDEX IF NOT EXISTS idx_unsubscribes_lookup
    ON support_unsubscribes(customer_email, store_subdomain);
```

#### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `customer_email` | TEXT | 退订邮箱（存储时统一 `trim().toLowerCase()`） |
| `store_subdomain` | TEXT | 退订的具体店铺 subdomain（如 `store-a`） |
| `email_type` | TEXT | 退订范围：NULL=该店铺全部邮件，具体值=只退订某类 |
| `source` | TEXT | 退订来源：`link`（点击退订链接）/ `manual`（管理员手动操作） |

#### 设计要点

- **复合唯一约束**在 `(customer_email, store_subdomain, email_type)` 上，防止重复退订
- `email_type` 预留扩展性：当前业务只需"全退"，但预留字段可支持未来按邮件类型退订
- 索引优化查詢性能，在每次发信前做 O(1) 级别的黑名单匹配

## 四、详细实现规格

### 4.1 `src/unsubscribe.ts` — 核心逻辑

```typescript
import crypto from 'crypto';
import { query } from './pg';
import { loadConfig } from './config';

// ── HMAC 签名 ──

function getUnsubscribeSecret(): string {
  // 复用 SUPPORT_TOKEN_SECRET，也可用独立环境变量
  const config = loadConfig();
  return config.tokenSecret;
}

function base64urlEncode(buf: Buffer): string {
  return buf.toString('base64')
    .replace(/\+/g, '-').replace(/\//g, '_').replace(/=/g, '');
}

function base64urlDecode(str: string): Buffer {
  str = str.replace(/-/g, '+').replace(/_/g, '/');
  while (str.length % 4) str += '=';
  return Buffer.from(str, 'base64');
}

/**
 * 生成退订链接的 HMAC 签名
 * @param email      买家邮箱（已 trim + lowercase）
 * @param storeSubdomain  店铺 subdomain
 * @param timestamp  可选：Unix 秒级时间戳，用于过期校验
 */
export function generateUnsubscribeSignature(
  email: string,
  storeSubdomain: string,
  timestamp?: number,
): string {
  const payload = timestamp != null
    ? `${email}|${storeSubdomain}|${timestamp}`
    : `${email}|${storeSubdomain}`;

  const hmac = crypto.createHmac('sha256', getUnsubscribeSecret());
  hmac.update(payload);
  return base64urlEncode(hmac.digest());
}

/**
 * 校验退订签名
 */
export function verifyUnsubscribeSignature(params: {
  email: string;
  storeSubdomain: string;
  timestamp?: number;
  sig: string;
}): boolean {
  const expected = generateUnsubscribeSignature(
    params.email,
    params.storeSubdomain,
    params.timestamp,
  );
  // 常量时间比较，防止时序攻击
  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(params.sig),
  );
}

/**
 * 构建完整的退订 URL
 */
export function buildUnsubscribeLink(params: {
  email: string;
  storeSubdomain: string;
  publicBaseUrl: string;
  includeTimestamp?: boolean;
}): string {
  const email = params.email.trim().toLowerCase();
  const store = params.storeSubdomain.trim();
  const ts = params.includeTimestamp
    ? Math.floor(Date.now() / 1000)
    : undefined;

  const sig = generateUnsubscribeSignature(email, store, ts);

  const url = new URL(`${params.publicBaseUrl}/unsubscribe`);
  url.searchParams.set('e', email);
  url.searchParams.set('s', store);
  if (ts) url.searchParams.set('t', String(ts));
  url.searchParams.set('sig', sig);
  return url.toString();
}

// ── 退订记录管理 ──

/**
 * 写入退订记录
 */
export async function recordUnsubscribe(params: {
  email: string;
  storeSubdomain: string;
  emailType?: string | null;
  source?: string;
}): Promise<void> {
  const email = params.email.trim().toLowerCase();
  await query(
    `INSERT INTO support_unsubscribes
      (customer_email, store_subdomain, email_type, source)
     VALUES ($1, $2, $3, $4)
     ON CONFLICT (customer_email, store_subdomain, COALESCE(email_type, '__all__'))
     DO NOTHING`,
    [email, params.storeSubdomain, params.emailType || null, params.source || 'link'],
  );
}

/**
 * 检查邮箱是否已退订某个店铺
 * @returns true = 已退订，应拦截
 */
export async function isUnsubscribed(
  email: string,
  storeSubdomain: string,
): Promise<boolean> {
  const r = await query(
    `SELECT 1 FROM support_unsubscribes
     WHERE customer_email = $1
       AND store_subdomain = $2
       AND email_type IS NULL  -- 全退
     LIMIT 1`,
    [email.trim().toLowerCase(), storeSubdomain],
  );
  return (r.rowCount ?? 0) > 0;
}

/**
 * 移除退订记录（管理员手动操作）
 */
export async function removeUnsubscribe(
  email: string,
  storeSubdomain: string,
): Promise<boolean> {
  const r = await query(
    `DELETE FROM support_unsubscribes
     WHERE customer_email = $1 AND store_subdomain = $2`,
    [email.trim().toLowerCase(), storeSubdomain],
  );
  return (r.rowCount ?? 0) > 0;
}

/**
 * 查询退订列表（管理员用）
 */
export async function listUnsubscribes(params: {
  storeSubdomain?: string;
  page: number;
  pageSize: number;
}): Promise<{ total: number; rows: any[] }> {
  const conditions: string[] = [];
  const values: (string | number)[] = [];
  let idx = 1;

  if (params.storeSubdomain) {
    conditions.push(`store_subdomain = $${idx++}`);
    values.push(params.storeSubdomain);
  }

  const where = conditions.length ? `WHERE ${conditions.join(' AND ')}` : '';
  const countR = await query(`SELECT COUNT(*) FROM support_unsubscribes ${where}`, values);
  const total = Number(countR.rows[0].count);
  const offset = (params.page - 1) * params.pageSize;

  const rows = await query(
    `SELECT id, customer_email, store_subdomain, email_type, source, created_at
     FROM support_unsubscribes ${where}
     ORDER BY created_at DESC
     LIMIT $${idx++} OFFSET $${idx++}`,
    [...values, params.pageSize, offset],
  );
  return { total, rows: rows.rows };
}
```

### 4.3 `src/mailer.ts` — List-Unsubscribe 邮件头

在 `sendSupportEmail()` 中，调用 `transporter.sendMail()` 时注入 `list` 属性：

```typescript
export async function sendSupportEmail(
  mail: SupportMail,
  opts?: { unsubscribeLink?: string; unsubscribeMailto?: string },
): Promise<{ messageId: string }> {
  const config = loadConfig();
  const transporter = await getTransporter();

  const sendOpts: any = {
    from: config.mailFrom,
    replyTo: config.mailReplyTo,
    to: mail.to,
    subject: mail.subject,
    html: mail.html,
    text: mail.text,
  };

  // ── RFC 8058 List-Unsubscribe 头 ──
  if (opts?.unsubscribeLink) {
    const unsubMailto = opts.unsubscribeMailto || config.mailFrom;
    // 优先使用 nodemailer 的 list 语法
    sendOpts.list = {
      unsubscribe: {
        url: opts.unsubscribeLink,
        comment: 'Unsubscribe from this store\'s notifications',
      },
    };
  }
  // ── 结束 ──

  const result = await transporter.sendMail(sendOpts);
  return { messageId: result.messageId || '' };
}
```

**注意**：阿里云 DirectMail 的 SMTP 网关是否支持自定义 headers 需要实测。如果不支持，退订仍然可以通过 HTML 底部链接正常工作，只是少了邮件客户端顶部的官方退订按钮。

### 4.4 `src/index.ts` — 注册退订路由

```typescript
// 退订页面与 API
app.get('/unsubscribe', async (req, res) => {
  const { e, s, t, sig } = req.query as Record<string, string>;
  
  // 参数完整性检查
  if (!e || !s || !sig) {
    return res.status(400).send('Invalid unsubscribe link: missing parameters.');
  }

  const email = String(e).trim().toLowerCase();
  const storeSubdomain = String(s).trim();
  const timestamp = t ? Number(t) : undefined;

  // 可选：过期检查（30天）
  if (timestamp != null) {
    const ageSeconds = Math.floor(Date.now() / 1000) - timestamp;
    const maxAge = 30 * 24 * 3600; // 30 days
    if (ageSeconds > maxAge) {
      return res.status(410).type('html').send(`
        <html><body style="font-family:Arial;text-align:center;padding:60px 20px;">
        <h2>Link Expired</h2>
        <p>This unsubscribe link has expired. Please contact support if you still wish to unsubscribe.</p>
        </body></html>
      `);
    }
  }

  // 签名校验
  const valid = verifyUnsubscribeSignature({ email, storeSubdomain, timestamp, sig });
  if (!valid) {
    return res.status(403).type('html').send(`
      <html><body style="font-family:Arial;text-align:center;padding:60px 20px;">
      <h2>Invalid Link</h2>
      <p>This unsubscribe link is invalid or has been tampered with.</p>
      </body></html>
    `);
  }

  // 签名有效 → 写入黑名单
  try {
    await recordUnsubscribe({ email, storeSubdomain });
  } catch (err: any) {
    console.error('[unsubscribe] record failed:', err.message);
  }

  // 返回确认页面
  res.type('html').send(`
    <html>
    <head>
      <meta charset="UTF-8">
      <meta name="viewport" content="width=device-width,initial-scale=1.0">
      <style>
        body { font-family: Arial, Helvetica, sans-serif; text-align: center; padding: 60px 20px; color: #333; }
        .checkmark { font-size: 64px; color: #52c41a; margin-bottom: 20px; }
        h1 { font-size: 22px; font-weight: 600; margin-bottom: 8px; }
        p { font-size: 14px; color: #595959; line-height: 1.6; }
        .store-name { font-weight: 600; color: #1890ff; }
      </style>
    </head>
    <body>
      <div class="checkmark">&#10003;</div>
      <h1>Successfully Unsubscribed</h1>
      <p>You have been unsubscribed from <span class="store-name">${escapeHtml(storeSubdomain)}</span> order notifications.</p>
      <p style="margin-top:24px;font-size:12px;color:#8c8c8c;">
        If you change your mind, you can still access your ticket via the original support link.
      </p>
    </body>
    </html>
  `);
});

function escapeHtml(s: string): string {
  return s.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;');
}
```

// GET /api/admin/unsubscribes — 查询退订列表
router.get('/unsubscribes', async (req, res) => {
  try {
    const page = Math.max(1, Number(req.query.page) || 1);

router.delete('/unsubscribes', async (req, res) => {
  try {
    const { email, store_subdomain } = req.body || {};
    if (!email || !store_subdomain) {
      res.status(400).json({ ok: false, error: '缺少 email 或 store_subdomain' });
      return;

      category: 'email',
      action: 'unsubscribe_removed',

      target: email,
      summary: `管理员移除退订: ${email}`,
      status: 'success',
    });
    res.json({ ok: true });
  } catch (e: any) {
    res.status(500).json({ ok: false, error: e.message });
  }
});

## 八、注意事项

1. **密钥不可更改**：`SUPPORT_TOKEN_SECRET` 一旦更换，所有已发邮件中的退订链接全部失效。
2. **URL 编码**：HMAC 签名使用 base64url 编码，避免 URL 中的 `+` `/` `=` 字符。
3. **邮箱大小写**：统一 `trim().toLowerCase()` 处理，避免 `User@Example.com` 和 `user@example.com` 被视为不同邮箱。
4. **性能**：`isUnsubscribed()` 查询依赖 `idx_unsubscribes_lookup` 索引，单次查询性能应在 1ms 以内。
5. **退订后依然能访问工单**：退订只影响邮件发送，买家仍可通过原有的 ticket access token 访问工单页面。
6. **日志记录**：每次退订拦截、退订写入、管理员移除都通过 `logOperation()` 记录到 `support_operation_logs` 表。
